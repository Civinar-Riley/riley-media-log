# 部署指南

书影集跑在 Cloudflare Workers + D1 上。本文按三条路线组织，按顺序做即可，每一步都附验证方法：

| 路线 | 目标 | 耗时 | 需要什么 |
| :--- | :--- | :--- | :--- |
| **A · 本地体验** | 在自己电脑上跑起来看看 | 约 5 分钟 | Node.js，不需要 Cloudflare 账号 |
| **B · 部署上线** | 部署到你自己的 Cloudflare，随时随地在手机上用 | 约 10 分钟 | 免费 Cloudflare 账号 |
| **C · push 即部署** | 以后 `git push` 自动发新版本 | 一次配置 | GitHub 仓库 + API Token |

> 路线 A 想长期用下去再走 B；B 做完就能正常使用了，C 是可选的省心项。

---

## ⚡ 一键部署（最快，约 2 分钟）

README 里点 **Deploy to Cloudflare** 按钮即可。Cloudflare 会自动：

1. 在你的账号里创建 D1 数据库并把 ID 写进配置（顶层的零值占位符就是留给这一步的）；
2. 按仓库里的 `.dev.vars.example` 提示你填写密钥（`AUTH_PASSWORD` / `SESSION_SECRET` / `API_TOKEN` 必填，两个自动补全 Key 可选）；
3. 构建并部署，完成后给你一个 `*.workers.dev` 站点地址。

> 部署完成后直接登录使用即可。国内访问 `workers.dev` 可能需要代理，或按「路线 B」第 7 步绑定自定义域名。
> 想手动一步步来、或要配 push 自动部署，看下面的路线 B / C。

| 工具 / 账号 | 说明 | 用在哪条路线 |
| :--- | :--- | :--- |

## 路线 A · 本地体验

1. **克隆并安装依赖**

   ```bash
   git clone https://github.com/Civinar-Riley/riley-media-log.git
   cd riley-media-log
   npm install
   ```

2. **创建本地密钥文件**：在项目根目录新建 `.dev.vars`（已被 gitignore，不会入库），写入三行：

   ```ini
   AUTH_PASSWORD=你的登录密码
   SESSION_SECRET=随便一串够长的随机字符
   API_TOKEN=随便一串随机字符（给脚本调 API 用的令牌，与登录密码无关）
   ```

   随机串可用 `openssl rand -hex 32` 生成。可选的两项自动补全 Key 见下方「配置一览」，不填完全不影响启动。

3. **初始化本地数据库**

   ```bash
   npm run db:migrate:local
   ```

   输出显示 5 个迁移文件依次应用成功即可。

4. **启动**

   ```bash
   npm run dev
   ```

   打开 `http://localhost:5173`，用 `.dev.vars` 里的 `AUTH_PASSWORD` 登录。

✅ **验证**：能登录、看到片单页（空列表正常）、能「记一笔」并保存。

> 想先看看功能长什么样：dev 跑着的情况下执行 `python scripts/seed_demo.py`，会灌入一套全部虚构的演示数据。

## 路线 B · 部署到 Cloudflare（正式使用）

0. **登录 Cloudflare**

   ```bash
   npx wrangler login
   ```

   会打开浏览器授权；完成后 `npx wrangler whoami` 应显示你的账号。

1. **创建 D1 数据库**

   ```bash
   npx wrangler d1 create riley-media-log
   ```

   复制输出里的 `database_id`。

2. **替换 `wrangler.jsonc` 顶层的 `database_id`**

   顶层配置是给一键部署按钮用的占位符（零值 UUID）——手动部署时把 `d1_databases[0].database_id` 换成上一步得到的真实值。作者自己的正式站/演示站配置在 `env.prod` / `env.demo` 里，与你的手动部署互不相干。

3. **应用数据库迁移**（建表）

   ```bash
   npm run db:migrate:remote
   ```

4. **配置 secrets**（密钥存在 Cloudflare，不进代码仓库）。必配三个：

   ```bash
   npx wrangler secret put AUTH_PASSWORD    # 登录密码
   npx wrangler secret put SESSION_SECRET   # 签名登录 cookie 的随机长字符串
   npx wrangler secret put API_TOKEN        # 脚本调用 API 的 Bearer 令牌
   ```

   每条命令回车后按提示粘贴值。可选项（自动补全功能）：

   ```bash
   npx wrangler secret put TMDB_API_KEY     # TMDB v3 API Key，themoviedb.org/settings/api 申请
   npx wrangler secret put BANGUMI_TOKEN    # Bangumi Access Token，next.bgm.tv/demo/access-token 生成
   ```

   不配这两个也能用，只是详情页「自动补全」会提示未配置；`BANGUMI_TOKEN` 不配时 Bangumi 公开数据仍可匿名查询。

5. **部署**

   ```bash
   npm run deploy
   ```

   输出末尾会给出站点地址：`https://riley-media-log.<你的子域>.workers.dev`。

6. **✅ 验证**：打开站点 → 登录 → 记一笔 → 统计页有数字 → 退出再登录一次确认会话正常。想迁移存量数据或灌演示数据，见下方「数据导入」。

7. **（可选）绑定自定义域名**：`workers.dev` 域名在中国大陆可能无法直连；在 Cloudflare 仪表盘 → Workers → 你的 Worker → Settings → Domains & Routes 里绑定一个自己的域名即可解决。

### 配置一览

| 项 | 配置位置 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `AUTH_PASSWORD` | `.dev.vars` / `wrangler secret put` | ✅ | 登录密码；也是忘记应用内密码时的应急登录通道 |
| `SESSION_SECRET` | `.dev.vars` / `wrangler secret put` | ✅ | 签名登录 cookie 的随机长字符串 |
| `API_TOKEN` | `.dev.vars` / `wrangler secret put` | ✅ | 脚本调 API 用的 Bearer 令牌 |
| `TMDB_API_KEY` | `.dev.vars` / `wrangler secret put` | 可选 | 自动补全（影视类）的 TMDB v3 Key |
| `BANGUMI_TOKEN` | `.dev.vars` / `wrangler secret put` | 可选 | 自动补全（书漫类）的 Bangumi Token，缺省走匿名 |
| `database_id` | `wrangler.jsonc` | ✅ | 替换为 `wrangler d1 create` 返回的真实 ID |

> ⚠️ **本地与线上的密钥是两套**：`.dev.vars` 只作用于本地 dev，线上要另外用 `wrangler secret put` 配置，改一边不影响另一边。
> ⚠️ **本地 dev 的自动补全需要代理**：本地跑时对 TMDB / Bangumi 的请求从你电脑直接出去，这两家在国内直连不通，需开系统代理；部署到 Cloudflare 后出网走边缘节点，无需任何代理。
> ⚠️ **所有密钥绝不入库**：`.dev.vars`、`*.xlsm`、`data/` 均已 gitignore，切勿把密码或个人数据提交进仓库。

## 路线 C · push 即部署（GitHub Actions）

仓库自带 `.github/workflows/deploy.yml`：**每次 push 到 `main`，自动执行 安装依赖 → 应用 D1 迁移（remote）→ 构建 → 部署**。配置一次，以后发版只需 push。

1. **把代码放进你的 GitHub 仓库**：直接 fork 本仓库，或新建仓库后 push。

2. **创建 Cloudflare API Token**：Cloudflare 仪表盘 → 右上角头像 → My Profile → API Tokens → Create Token，权限需包含 **Edit Cloudflare Workers** 与 **D1 Edit**（迁移和部署都要用）。

3. **在 GitHub 仓库配置两个 Secret**：Settings → Secrets and variables → Actions → New repository secret

   | Secret 名 | 值 |
   | :--- | :--- |
   | `CLOUDFLARE_API_TOKEN` | 上一步创建的 Token |
   | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare 仪表盘首页右侧（或任意域名概览页）的 Account ID |

4. **push 到 `main`**（或在 Actions 页手动 Run workflow），等跑完变绿勾。

✅ **验证**：Actions 运行成功后，打开站点确认新改动已生效。

> 得益于这个流水线，**数据库升级也是自动的**——CI 在部署前先执行 `wrangler d1 migrations apply --remote`，push 里带新迁移文件即可，无需手动操作。

## 数据导入（可选）

| 场景 | 操作 |
| :--- | :--- |
| **导入自己的存量资料** | 照 `docs/import-template.json` 把资料整理成 JSON（除标题外都可以不填，缺的之后用「自动补全」补齐）→ `python scripts/import_json.py --input 你的资料.json`；导入线上站点加 `--base https://你的站点 --token <API_TOKEN> --allow-remote`（国内访问还需 `--proxy`）。默认按「标题+年份+类别」查重跳过已有条目，类别/状态/完结状态都支持中文写法 |
| **灌一套演示数据** | dev 跑着时执行 `python scripts/seed_demo.py`（全部虚构片名，用于体验或截图；做截图建议把 `wrangler.jsonc` 的 `database_id` 临时改成 `demo-screenshots`，避免污染真实数据，用完改回） |
| **API 回归测试** | dev 跑着时执行 `python scripts/qa_sweep.py`（以当前库为基准的相对断言，自建自清临时数据，不碰真实数据） |
| **批量补全元数据** | `python scripts/backfill.py`（配合 TMDB / Bangumi），用法见 README「使用指南」 |

## 日常更新与升级

1. `git pull` 拉最新代码；
2. `package-lock.json` 有变化时执行 `npm install`；
3. 发布：配了路线 C 直接 `git push`；否则自己执行 `npm run deploy`（迁移已在 CI 自动应用；手动执行可用 `npm run db:migrate:remote`）。

迁移文件**只追加、不修改**历史，任何旧版本都能按顺序升到最新版；涉及新增 secret 或迁移要求的升级，`CHANGELOG.md` 的「升级须知」会用醒目方式标注。

## 部署常见问题

| 现象 | 原因与解决 |
| :--- | :--- |
| 站点在国内直连打不开 / 超时 | `workers.dev` 域名被墙，属正常现象；挂代理访问，或按路线 B 第 7 步绑定自定义域名 |
| 详情页「自动补全」提示未配置 | 没配 `TMDB_API_KEY`：线上用 `wrangler secret put` 配，本地写进 `.dev.vars`（两处独立） |
| 本地 dev 自动补全报网络错误 | 本地直连 TMDB / Bangumi 被墙，开系统代理即可；线上部署后无此问题 |
| 批量脚本被 Cloudflare 拦（1010） | 脚本已带浏览器 UA 可过 TLS 指纹检测；访问线上站点还需 `--proxy http://127.0.0.1:<你的代理端口>` 之类的代理参数 |
| 部署时迁移报错 | 检查 `wrangler.jsonc` 的 `database_id` 是否已替换为你自己的，以及 API Token 是否含 D1 Edit 权限 |
| 其它奇怪报错 | 先翻 [防踩坑.md](../防踩坑.md)：开发与部署中真实踩过的坑都有现象与解法 |
